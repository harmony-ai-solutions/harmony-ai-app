### 0.2 Remaining blockers (design-level, not missing routes)
1. **Engine mints entity ids; the app mints client-side.** `POST /api/entities`
   *rejects* any body carrying `id`/`alias` (400) and derives the id server-side
   from `name`; there is no "derive my id" endpoint. The app's five creation seams
   pre-mint via `mintEntityId` and pass the id + alias into `createEntity`, then
   reuse that id for the module mapping, navigation and profile linkage. Repointing
   is a create-then-read-id rewrite across `CreateAIScreen`, `CharacterChatService`,
   `PersonaEditScreen`/`createUserPersona`, `CharactersScreen`, `AIProfileScreen`
   (`duplicateAIPartner` alone is a clean wrapper). Per the owner ruling's halt
   clause, `mintEntityId` has no engine equivalent that returns an id without
   creating. See `3-4-resume-findings.md` §C.
2. **Engine mints character-profile ids.** `POST /api/character-profiles` ignores a
   client `id` (fresh uuid). Same rewrite. §D.
3. **Module-config wire shape mismatch.** Engine module-config reads/writes use a
   composite shape (`{id, name, provider, <providerType>: {...}}`); the app's
   models are flat (`provider_config_id`). The existing 3-2 read adapter is
   type-lying; write bodies are `{name, config}`. Needs a real mapper + a
   create-flow rework. §E.
4. **Character image writes are multipart**, not base64 JSON. §F.
5. **D-35 send/ingest redesign** — behavioural (in-memory pending rows + engine-
   authored rows + reconcile), touches `EntitySessionService` + `ChatDetailScreen`.
   §G.
6. **Deletion blast radius** — `SyncConnectionContext` (1346 lines) + the sync/
   cloud stack woven through contexts/screens/tests. §H.

### 0.4 Closed this pass ✅ (2026-10-12 deletion pass)

1. **D-35 (send/ingest redesign) — DONE.** `EntitySessionService` keeps the
   session machinery but no longer mirrors messages into SQLite: outgoing sends
   register an optimistic **in-memory pending row** (`pending-…` key, no
   app-authored engine id) and fire the WS ENTITY_UTTERANCE; incoming
   ENTITY_UTTERANCE events drive a UI refresh; `reconcilePendingMessages`
   drops a pending row once the engine-authored counterpart appears on the next
   engine read (matched by type + content + sender + a 10s timing window).
   `ChatDetailScreen` renders `messages ∪ pendingMessages` and reconciles on
   every engine read. Engine echo semantics were verified read-only: the engine
   **discards the app's `message_id`** (`utterance.MessageID =
   utils.GenerateMessageID()`) and does **not** echo the user's own utterance
   back — only the AI's response — so reconciliation is against the engine READ,
   not a WS echo.
2. **Sync/cloud connection-context rewrite — DONE.** `SyncConnectionContext`
   is reduced from 1346 lines to an engine-connection status context (connect /
   disconnect / reconnect + status; no SyncService, no cloud session, no purge,
   no server-update gate). `connectionStatusHelper` is simplified. The
   sync/cloud settings + connection-setup screens, the cloud provisioning/purge
   components and the development DB viewer are deleted; navigation is
   coherent.
3. **Atomic deletion — DONE.** `src/database/` (connection/transaction/RN
   database/sync/migrations/pkRegistry/index/types/README + 47 migrations +
   the SQLite repositories + providers + `__test_utils__` + `__tests__`),
   `SyncService` + `syncNameClash` + `WipeRebuildFlag` + `AppRestart`,
   `CloudSessionService`, the estimate/settlement helpers, the schema-parity
   tooling (`scripts/dump-schema.ts`, `compare-schemas.py`,
   `parity-allowlist.json`), and the dropped deps
   (`react-native-sqlite-storage`, `react-native-restart`, `better-sqlite3` +
   their `@types`) are gone. Consumers (`AuthContext`, `DatabaseContext`,
   `DatabaseLoadingScreen`, `FloatingChat`, `soulbitsTokenSync`,
   `CharacterChatService`, `EntitySessionService`, the screens) are rewired;
   `createWebSocket` no longer reads `process.env`.
4. **Mute is engine-authoritative — DONE.** `setEntityMuted` → `PUT
   /api/entities/:id` `{is_muted}`; `getMutedEntityIds` reads the entity
   config's `is_muted`; the app-local `EntityMutePreference` AsyncStorage
   overlay is deleted.
5. **Gates.** `npx tsc --noEmit` = 0; `npm test` green (104 unit suites / 823

## 8. Flag flip (step 1d) — DEFERRED with the deletion

`src/config/engineFeatures.ts`: `ENGINE_API_DATA_LAYER_DEFAULT` stays **false** until the relink is complete. Rationale: with the flag ON today, **reads** dispatch to the engine API while **writes** (providers, entity/profile/module writes, D-35 mirror) remain SQLite-backed — a create would be invisible to the subsequent API read. The 3-4 doc's "flip default ON" is the *consequence* of a complete relink, not a step that can precede it. `ENGINE_SIDECAR_ENABLED` force-on is likewise sequenced with the flag.
